# band_channel 手机 NPU 热点与 Div 优化分析

## 结论

截图中最重的三个 Div 都是第一级 Haar 高频的动态 smooth 收缩，合计 **26.00%**。阈值已经离线固化，但除数仍包含输入系数的绝对值，不能把整个除法当成常数离线计算，也不能直接删除。优先考虑同层三个子带合并处理，以及目标 SDK 支持的算子融合；允许近似时，再比较分段线性收缩、量化查表或 soft-threshold 微调。

另一个优先级很高的**数学等价**优化是将第一级 IWT 与其后的 S2D 合并为低分辨率的 1×1 通道变换，再考虑与 stem 卷积合并。它对应截图中 **6.04% + 4.27% = 10.31%** 的两个节点，但不能把这部分占比直接当作最终可节省的时间。

本文只分析并提出后续实验方案，没有修改部署模型或导出新版本。

## 十个 Div 的完整定位

| ONNX 名称 | 层级/子带 | 元素数 | 分母是否常量 |
|---|---|---:|---|
| `/wavelet/Div`、`Div_1`、`Div_2` | LH1、HL1、HH1 | 各 230,400 | 否 |
| `/wavelet/Div_3`、`Div_4`、`Div_5` | LH2、HL2、HH2 | 各 57,600 | 否 |
| `/wavelet/Div_6`、`Div_7`、`Div_8` | LH3、HL3、HH3 | 各 14,400 | 否 |
| `/wavelet/Div_9` | LL3 网络输入归一化 | 14,400 | 是，8 |

九组高频采用：

```
u = abs(z)
gain = u / (u + T)
y = z * gain
```

离线表 T 已包括 `softplus(logit) × 2^level`，推理时不再计算 softplus 或额外的高频 scale。实际 level 1 四通道阈值为：

| 子带 | 通道0 | 通道1 | 通道2 | 通道3 |
|---|---:|---:|---:|---:|
| LH1 | 0.005166160 | 0.004885716 | 0.006639128 | 0.007736247 |
| HL1 | 0.005130290 | 0.006766694 | 0.005856584 | 0.009293586 |
| HH1 | 0.019559497 | 0.020585200 | 0.025666989 | 0.013703476 |

阈值固定不意味着增益固定。把增益也改成每通道常数将失去按系数幅度抑制噪声的行为。

## 优先尝试的等价优化

### 1. 合并同层高频，减少逐子带调度

将 Haar 输出按 `[LL(4ch), HF(12ch)]` 分组，HF 维持 LH/HL/HH 的顺序，使用 `[1,12,1,1]` 的阈值：

```
HF_filtered = HF * (abs(HF) / (abs(HF) + T12))
```

三层合计由 9 组 Abs/Add/Div/Mul 降为 3 组。阈值表和数学结果不变；元素总数和除法次数不变，收益来自调度、向量化及可能的融合，不能承诺 Div 耗时降为三分之一。应直接从 DWT 输出取得连续 12 通道，避免先拆三份再 Concat 而抵消收益。

若 SDK 支持自定义融合算子或图模式融合，可将 Abs→Add→Div→Mul 合成一个收缩算子，尽量让中间值驻留片上。其实现与可行性依赖具体 NPU 工具链。

### 2. 消除常量 Div_9，但同时处理 LL 融合旁路

简单导出 `LL3 * 0.125` 可把 Div 改为 Mul，但后端也可能已经这样优化，且它不是截图前三个 Div。

进一步完全折叠归一化：设 `x=LL3`，CNN 为 `f`，LL 融合权重分成 `[A,B]`，偏置为 `b`。原输出：

```
8 * (A*f(x/8) + B*(x/8) + b)
```

将 CNN 第一层权重改为 `W_first/8`、第一层偏置保持不变，使新 CNN 输入直接为 x；融合权重改为 `[8A, B]`，融合偏置改为 `8b`。即可去掉输入 Div_9 和输出 ×8，并保留 LL 旁路语义。不能只改第一层而遗漏归一化后的 LL 拼接分支。此处针对当前 concat_1x1、ll_only 结构，需验证全部边界和符号输入。

### 3. 合并最后一级 IWT 与主路 S2D

当前路径：`C=[LL1',LH1',HL1',HH1'] → IWT → I− → S2D → stem`。

2×2 Haar IWT 没有块间重叠，S2D 正好重新收集同一个 2×2 空间块。因此 `S2D(IWT(C)) = M*C`，其中 M 是固定 16×16 的通道矩阵，可实现为低分辨率 1×1 卷积。

对任意 RAW 通道，输出四个像素为：

```
p00 = (LL + LH + HL + HH)/2
p01 = (LL - LH + HL - HH)/2
p10 = (LL + LH - HL - HH)/2
p11 = (LL - LH - HL + HH)/2
```

矩阵输入按 band-major 排列，输出必须按 packed S2D 的 channel-major 顺序排列，不能忽略此置换。再把 M 乘入 stem 的输入通道权重：`W_new[o,j,h,w] = sum_i W_stem[o,i,h,w]*M[i,j]`，stem bias 不变。可同时消除末级 IWT 和主路 S2D，而不是仅分别加速它们。

这要求精修直接消费小波子带；默认完整图中 I− 没有其他消费者才适用。仅导出最终输出、当前尺寸可被 8 整除时最直接。请求 I− 调试输出或奇数尺寸裁剪时要单独处理。Concat_2 仍可能作为新 stem 的输入存在；分支卷积相加虽能避开 Concat，却会增加算子和调度，需测速决定。

### 4. 末端 fusion 1×1 与 D2S 合并

当前 `Conv1×1(32→16) → D2S(16→4)` 可合成为 stride 2、kernel 2 的 `ConvTranspose(32→4)`，把 16 个输出通道权重按四个子像素位置填入反卷积核。

**偏置不能随意丢掉**：原 16 个偏置可能对应四个不同空间相位，普通 ConvTranspose 的 4 个偏置通常不能表达它。可使用零 bias 的反卷积 + 固定空间相位偏置图；这又引入加法/常量存储。只有每个输出通道的四个相位偏置相等，才可直接用单个标准反卷积表示全部操作。量化融合也需单独核实。

### 5. 原输入的 DWT1 与旁路 S2D 复用

DWT1 和旁路 S2D 都读取同一个 I。可只生成一次 S2D(I)，通过固定 1×1 Haar 矩阵生成 DWT1 输出；或者从完整 DWT1 输出通过固定逆矩阵得到 S2D(I)。二者数学等价，但仍需额外 1×1、改变张量生存期，NPU 是否更快不确定。禁止使用已经收缩的高频重建原 I 的旁路，否则会改变模型功能。

## Div 的替代：哪些需要误差评估或微调

### Reciprocal + Mul

`u/(u+T)` 可写为 `u * Reciprocal(u+T)`。这不是移除动态倒数，可能增加算子，亦可能由后端自动转换。仅当 SDK 对 Reciprocal 有更优内核或能融合时值得测试；浮点舍入路径不同，仍需误差验证。

恒等式 `y = z - z*T/(abs(z)+T)` 同样保留动态除法，还可能产生相消，不建议作为首选。ONNX 的普通 Div 不会因为 T 固定就变成纯常量运算。

### 归一化后的分段线性或真正 LUT

令 `v=z/T`，则 `y=T*h(v)`，`h(v)=v*abs(v)/(abs(v)+1)`。T 和 1/T 均可离线保存，用常量乘法完成归一化；把通用 h 用 PWL 或硬件 LUT 近似，才可能去掉动态 Div。

- 用真实 SID 校准集统计各子带/通道的 `abs(z)/T` 分布，重点覆盖零附近、约 1 的过渡区和大幅度尾部；不要使用最终测试集拟合。
- 多段 ReLU 形式可表达 PWL，但若 SDK 不融合，节点数/带宽可能比 Div 更差。
- 真正的量化 LUT 需要索引、舍入、Gather 或厂商原语；“36 个阈值表”不是这类对系数取值查表的非线性 LUT。浮点系数是连续的，有限表必然涉及量化或插值。
- 大幅度时 h(v) 接近 `v-sign(v)`，不是严格的 v；设计尾部时注意绝对误差。
- 若增益近似误差为 δ，则单系数输出误差为 `z*δ`。后续 LL/精修网络可能放大或抑制误差，不能由该局部误差直接保证最终 PSNR。

建议把近似算子放入学生网络做短期微调，或用当前模型输出蒸馏，再比较真实 pair 的 PSNR 与纹理细节。

### soft threshold 对照

用 `ReLU(z-T)-ReLU(-z-T)` 替代 smooth，可去掉 Abs/Div，但它与当前函数不等价：例如 z=T 时 smooth 输出 T/2，soft 输出 0；soft 对 |z|≤T 产生零梯度区。不能仅用同一阈值替换后称无损优化。

可新建 `dwt_shrink_mode: soft` 对照，从当前模型初始化后微调，重新学习 36 个阈值及必要的精修参数。也可考察 firm/PWL 收缩。最终收益需由 NPU 实测与 SID 指标共同判断。

## 建议实验顺序与验收

| 顺序 | 方案 | 数学属性 | 验证重点 |
|---|---|---|---|
| 1 | 同层 12 通道高频合并 | 等价，浮点容差 | 三个层级/全部通道、Split 布局、真实 NPU 延迟 |
| 2 | 最后 IWT+S2D→1×1，进而折叠进 stem | 等价，浮点容差 | 通道顺序、边界、输出尺寸；ConvTranspose 是否减少 |
| 3 | LL /8、×8 折叠 | 等价，浮点容差 | LL 拼接旁路和融合偏置 |
| 4 | SDK 收缩融合或 Reciprocal 改写 | 后端相关 | 子图落点、访存、实际反汇编/编译日志 |
| 5 | PWL/LUT、soft threshold + 微调 | 近似/新模型 | 校准范围、真实 SID PSNR、暗部纹理/色偏 |

每次只改一项并保留模型 hash。按当前导出验证 uniform、signed RAW、零输入、极小输入，增加接近阈值的系数、饱和区域与完整 SID ratio 100/250/300 样本。等价修改先用 FP32 对照，再评估手机实际精度（FP16/INT8）；特别检查小阈值、除数下溢和反量化尺度。

手机侧记录 SoC、SDK/驱动、精度、后端分区、输入布局、预热次数、重复次数、温度/频率及端到端 median/P95；区分是否包括传输和预处理。节点百分比可能来自 profile 的串行归因，优化后的融合/调度会变化，不能简单相加预测总延迟。

假设截图百分比可按端到端串行时间解释，即使前三个 Div 完全免费，单凭这部分的理论上限也只是 `1/(1-0.26)≈1.35×`；若其耗时减半，约 `1/(1-0.13)≈1.15×`。这仅是 Amdahl 示意，不是速度承诺。

## 后续需要的手机信息

要将“候选优化”缩小为可执行的 NPU 方案，需要手机 SoC/NPU 型号、转换工具与版本、FP32/FP16/INT8 模式、完整 profile 的绝对耗时和后端落点。尤其需确认 Div/Abs 是否实际留在 NPU，以及 ConvTranspose 的硬件执行方式。当前证据足以定位图中公式与等价关系，尚不足以判定硬件瓶颈的具体实现原因。
