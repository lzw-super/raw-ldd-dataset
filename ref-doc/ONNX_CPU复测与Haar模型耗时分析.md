# Haar + LL-RepNCB 与 MRLFN 的 CPU 复测和瓶颈分析

日期：2026-09-22。结论：Haar 模型卷积本身更省时，但非卷积与内存布局开销抵消了优势；LL 恢复分支不是主要瓶颈。

## 方法

使用现有重参数化部署 ONNX，固定 FP32 `[1,4,360,640]`，ONNX Runtime GPU 包 1.18.0 的 CPUExecutionProvider。Xeon Gold 6530，分别测试 intra_op=1/4，inter_op=1；关闭线程空转（allow_spinning=0），防止两个同时驻留 session 的线程池相互争抢。未绑定 NUMA/CPU，机器仍有其他任务。

每模型预热 10 次；三个轮次交替改变模型测试先后顺序，每轮计时 20 次，总计 60 次。计时包含 session.run，不含加载。与上一份报告的时间不同：系统负载与 allow_spinning 设置不同，因此不应把两轮差异当成模型变化。

## Haar 各部分耗时（4线程 profiling）

另起 session 开启 ORT profiling，执行 15 次，丢弃前 5 次，将后 10 次的逐节点耗时取均值。下表按原 ONNX 节点名称/图位置归属；ORT 自动添加的布局转换单列，没有强行分摊给 CNN。卷积可能已经融合激活。profiling 本身有开销，节点总和不应与上面的非 profiling 延迟严格相等。

## 为什么 FLOPs 低但没有更快

| 模型 | Conv 节点总耗时 ms | 非 Conv 节点总耗时 ms |
|---|---:|---:|
| haar | 52.308 | 69.975 |
| mrlfn | 92.185 | 22.168 |

Haar 的 Conv 节点时间显著更短，与较低卷积运算量一致。但 FLOPs 无法直接衡量内存读写、Transpose/Slice/Concat、分配与调度开销。原训练 profile 还明确注明仅统计 CNN MACs，排除 functional DWT/IWT 和 atlas/shrink 操作，因此“约 2G / 4G”不覆盖完整部署图；本次没有把这两个估算值当成重新计算的全图 FLOPs。

关键观察：

- Haar 中两次 S2D 的 Transpose 分别约 7.51 / 7.19 ms，加上 D2S 等合计约 17.69 ms。
- Softplus 单节点约 6.97 ms；阈值生成与收缩整体约 12.12 ms。
- ORT 的 ReorderInput + ReorderOutput 合计约 15.74 ms，MRLFN 约 1.88 ms。其余未归属节点另外计入上表“布局转换及未归属节点”。
- Haar 的 Slice 约 8.29 ms；小波变换/atlas 运算涉及多次数据搬运。
- LL 恢复仅约 1.73 ms；进一步删减 LL 分支预计只能节省有限时间。
- 虽然原始图有大量 ScatterND，但不能由节点数量断言其最慢；优化后实际主要热点是卷积、Transpose、重排、Slice 和 Softplus。

## 后续优化方向（尚未修改模型）

1. 优先优化部署图的数据布局，减少 NCHW 与 ORT 内部布局之间的反复转换；结合 PReLU 导致融合受限的图结构进一步核实。
2. 研究 S2D 与前置/后置卷积的等价融合，避免显式 transpose；必须验证通道顺序和边界等价性。
3. 将固定 Haar 的切片算术路径改为部署友好的固定滤波/重排实现，并移除 atlas 的冗余拼接和静态映射构建，再做数值和耗时对照。
4. 固定尺寸下预计算尺度/掩码；确认已被常量折叠的节点不再重复优化。Softplus 属于非线性操作，近似替换需要额外精度验证。

这些是根据当前 profile 提出的优化候选，不是已验证的提速承诺；本轮没有更改原模型或 ONNX 文件。

本节复用上面同一轮 4 线程 ORT profiling 的数据，均为预热后 10 次节点耗时均值，没有混入新一轮计时。块内部包含部署卷积、融合激活、线性卷积和残差 Add；ORT 自动添加的 Reorder 独立列出。

|---|---:|---:|

| 浅层 3×3 卷积 | 3.141 | 2.7% |
| mRLFB 1 | 21.305 | 18.6% |
| mRLFB 2 | 20.877 | 18.3% |
| mRLFB 3 | 21.766 | 19.0% |
| mRLFB 4 | 20.218 | 17.7% |

| 浅层融合卷积 | 0.564 | 0.5% |

四个 mRLFB 合计 **84.166 ms（73.6%）**，是 MRLFN 的主要耗时来源。

### 按功能大类对比

两模型并非一一对应架构。下表把学习网络、显式空间重排、小波专有处理及运行时开销分组，以便比较；每列各类别互不重叠。

| 功能大类 | Haar + LL-RepNCB ms | MRLFN d32 ms |
|---|---:|---:|
| 学习网络与特征融合 | 59.169 | 96.341 |
| 显式 S2D / D2S | 17.689 | 16.131 |
| DWT/IWT、atlas、阈值及收缩 | 28.021 | 0.000 |
| 运行时布局转换及未归属节点 | 17.404 | 1.880 |
| 节点耗时合计 | 122.283 | 114.353 |

Haar 的学习网络与融合部分明显更快，但它多出小波和阈值处理，且布局转换更频繁。两者显式 S2D/D2S 均有显著开销，不能把 MRLFN 当成没有重排成本的纯卷积网络。MRLFN 的热点主要是主干卷积；Haar 的优化重点应放在小波/阈值路径和布局转换，而不是占比很低的 LL 恢复模块。

此处节点合计约 122.28 / 114.35 ms；非 profiling 的端到端均值是 123.55 / 108.76 ms。二者来自不同计时方式，不应相减或混合计算模块占比。
