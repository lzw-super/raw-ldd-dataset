# 特定手机传感器数据采集、标定与训练流程

> 适用对象：当前仓库、`raw-test` 中的 HONOR MEY-AN00 DNG，以及后续要补采的真实 noisy-clean 对。
> 数据审计日期：2026-07-28。本文区分“已经从文件验证的事实”“建议的实现”和“仍需补采/实验确认的假设”。

## 1. 结论先行

1. **可以优先使用 DNG 的 `NoiseProfile`，不再使用论文的 `K=ISO/1000` 假定。** `NoiseProfile` 给出黑电平扣除、满量程归一化域中的

   \[
   \operatorname{Var}(x_c)=S_cx_c+O_c.
   \]

   在这个域中，shot-noise 的等效斜率就是 `S_c`；在当前 DNG 的 DN 域中则是

   \[
   K_{c,\mathrm{DN}}=S_cL,\qquad L=W-\max_p b(p).
   \]

   但它是手机 HAL 已标定并按本次 sensitivity 求值的等效 Poisson-Gaussian 参数，不是从这一张照片临时估计出来的，也不能仅凭它分解出绝对 QE、模拟增益和电子数。更准确的名称是“DNG 模型下的等效 K”。

2. **训练与暗帧匹配必须使用 DNG 中的最终 EXIF ISO 和 `NoiseProfile`，不能使用文件夹名。** 本批文件的文件夹标称值与 EXIF 基本为 2 倍关系，例如 `160 -> 319`、`640 -> 1278`。这不是 DNG 规范规定的换算；缺少采集 app 的 request/result 日志时不能猜原因，更不能擅自把 EXIF 除以 2。

3. **推荐使用混合噪声合成：`NoiseProfile.S` 生成 shot noise，真实暗帧 residual 提供读出噪声、行列噪声、量化噪声等信号无关项。** 此时不要再额外采样 `O` 高斯项，否则会重复计算信号无关噪声。`O` 用作暗帧统计校验和没有真实暗帧时的 fallback。

4. **当前 `raw-test` 可用于元数据建表、1/30 s 条件的初步 Dark Shading（有时被写成 Dark Shadow）/残差建模和合成训练原型，但还不能作为最终训练/评测集。** 现有 90 张所谓 clean DNG 都是单张 10 s 曝光，包含高 ISO、饱和和可见噪声；它们没有构成真实 noisy-clean 对，也没有同场景 burst 平均得到的高 SNR ground truth。

5. **当前数据量下优先从 SID 上训练好的 `sid_sony_nafnet_tiny` 全网络低学习率微调，同时保留从头训练作为对照。** 本地完整权重是 `experiments/sid_sony_nafnet_tiny/checkpoints/latest.pth`（epoch 1000，1,288,000 step）。手机数据管线适配完成后应通过 `--init-checkpoint` 只初始化模型；不要用 `--resume` 恢复已经结束的 SID optimizer/scheduler。

## 3. 正确解释和使用 DNG `NoiseProfile`

### 3.1 标签含义与单位换算

当前文件的 tag 51041 含 6 个 double：

```text
(S_R, O_R, S_G, O_G, S_B, O_B)
```

它按 `CFAPlaneColor=[R,G,B]` 排列，不是 4 个 Bayer 位置。DNG 的标准处理顺序是先应用可选 `LinearizationTable`，再逐像素减去

\[
b(p)=BlackLevel(p)+BlackLevelDeltaH(p)+BlackLevelDeltaV(p),
\]

然后对每个 sample plane 使用统一分母

\[
L=W-\max_p b(p),\qquad x_c(p)=\frac{d_c(p)-b(p)}{L}.
\]

当前 DNG 没有 `LinearizationTable` 和 BlackLevel delta，且 `SamplesPerPixel=1`，所以每帧只有一个标量 `L`，再 broadcast 到四个 packed 通道。DNG 噪声模型是

\[
\operatorname{Var}(x_c)=S_cx_c+O_c.
\]

通用 parser 还必须接受 tag count=2（一个 `S/O` 对用于全部颜色）或 count=`2×ColorPlanes`，不能把“本机恰好为 6”硬编码成 DNG 的唯一合法形式。

换回去黑电平的 DN 信号 `s_c=d_c-b=Lx_c`：

\[
\operatorname{Var}(s_c)=\underbrace{LS_c}_{K_{c,\mathrm{DN}}}s_c
+\underbrace{L^2O_c}_{\sigma^2_{0,c,\mathrm{DN}}}.
\]

因此：

```python
profile_rgb = np.asarray(noise_profile, dtype=np.float64).reshape(3, 2)
S_rgb = profile_rgb[:, 0]
O_rgb = profile_rgb[:, 1]
black_map = expand_dng_black_level(tags)
L = float(white_level) - float(black_map.max())
K_dn_rgb = S_rgb * L
sigma0_dn_rgb = np.sqrt(O_rgb) * L
```

如果训练一直在 DNG 定义的归一化域，直接使用 `S` 和 `O`，不必先计算 `K_dn`。若代码自行改用逐位置 `W-b(p)` 或另一个分母 `A`，这已经是不同于 DNG 定义的归一化，必须同步换算：

\[
S'=\frac{L}{A}S,\qquad O'=\left(\frac{L}{A}\right)^2O.
\]

当前最低档样本（EXIF ISO 200）的完整 profile 是：

```text
R: S=6.4869836576e-05, O=4.8384335440e-07
G: S=1.0547167307e-04, O=1.7236341049e-08
B: S=7.7120744893e-05, O=4.1983406064e-07
```

使用 `L≈959` 得到 `K_R/G/B≈0.0622/0.1011/0.0740 DN`，明显不是论文按 EXIF ISO 得到的统一 `0.2 DN`。最高档 EXIF ISO 8000 的实际 K 约为 `1.175/1.201/1.204 DN`，也不是论文公式的 `8 DN`。

### 3.2 能否称为“真实 K”

可以把 DNG profile 作为本手机、当前 sensor mode 和本次实际 ISO 下的**首选等效 K**，它比论文根据 base ISO/QE 猜一个比例可靠得多；但不应声称它是无模型假设的物理真值，原因是：

- 它本身仍假定 `Var=Sx+O`；不描述 PRNU、固定图样、空间热效应、行列相关噪声和异常像素。
- 本批同 ISO 文件的 profile 完全相同，说明它是 HAL 标定模型的查表/求值结果，不是逐帧像素估计。
- AOSP Camera ITS 的通用增益形式包含 analog gain（AG）和 digital gain（DG）：`S=a·AG·DG+b`、`O=(c·AG²+d)·DG²`。只有在 DG=1、sensitivity 与 AG 对应的纯模拟段才简化为常见的 `S=a·ISO+b`、`O=c·ISO²+d`；当前手机这 9 档恰好近似该简化形式，但不能据此跨数字增益/DCG 段外推。
- AOSP `DngCreator` 会在 Camera2 的两个绿色 CFA profile 中选择 `S` 较大的整对 `(S,O)`，写成 DNG 的一个 G profile；它不是两绿平均。因此仅从当前 DNG 不能恢复 Gr/Gb 的独立差异。若需要两个绿色的参数，采集 app 应额外保存原始 `CaptureResult.SENSOR_NOISE_PROFILE` sidecar，或分别对两个 Bayer 位置做 PTC。
- 手机切换 DCG、数字增益、binning、HDR、镜头或 RAW mode 后，必须重新验证，不能跨模式套用同一拟合。

推荐的优先级是：

1. 每个训练样本直接读取自身 DNG `NoiseProfile`；
2. 同一实际 ISO、同一 mode 的 profile 相同时，缓存为查找表；
3. 缺少某档时，只在同一 mode/增益段内插值；
4. 用少量平场 PTC 抽验 `S`，而不是重新假定 `K=ISO/1000`；
5. 只有没有 `NoiseProfile` 时，才使用按 ISO 拟合或论文的宽范围 K 假设作为 fallback，并明确标记实验分支。

## 4. RAW 预处理与 CFA 通道约定

### 4.1 当前手机的 canonical packing

当前 mosaic 的 2×2 相位是：

```text
TL=G   TR=B
BL=R   BR=G
```

SID Sony 权重训练时看到的是 `[R,G1,G2,B]`。为了复用权重，手机数据不能沿用现有 `pack_bayer()` 的纯位置顺序 `[TL,TR,BL,BR]`，而应固定定义：

```text
raw position order: [G_TL, B_TR, R_BL, G_BR]
canonical order:    [R_BL, G_BR, G_TL, B_TR]
position indices:   [2, 3, 0, 1]
```

这个置换恰好是自身的逆置换，但实现中仍应分别提供 `pack_canonical()` 和 `unpack_to_dng_cfa()`，并做逐像素 round-trip 单元测试。两个绿色的顺序一旦确定就不能在训练、验证、推理之间变化。

相应的参数展开为：

```python
# profile rows are R/G/B; canonical packed order is R/G_BR/G_TL/B.
S4 = np.array([S_R, S_G, S_G, S_B])
O4 = np.array([O_R, O_G, O_G, O_B])
black4 = black_position_order[[2, 3, 0, 1]]
L = white_level - black_map.max()  # DNG standard normalization; scalar here
range4 = np.full(4, L)
```

若使用 `DefaultCrop`，必须先检查 crop origin 对 CFA 相位的影响；当前 origin `(8,8)` 为偶数，不改变上述相位。不要假定其他手机也如此。

### 4.2 每帧 Black/White Level

按 DNG 规则应用可选 linearization，把 `BlackLevelRepeatDim`、`BlackLevel` 和可选 delta 展开为位置图，再做：

\[
x_c(p)=\frac{d_c(p)-b(p)}{W-\max_p b(p)}.
\]

当前文件虽接近 64/1023，但不同 ISO 的 RATIONAL BlackLevel 有 63.87、63.93 和 64.00 等差异。manifest 必须保存原始值；训练时不能使用当前 SID 代码里的 512/16383，也不能把 16-bit container 当作 16-bit 有效动态范围。

BlackLevel repeat pattern 和 `DefaultCropOrigin` 都以 ActiveArea 为坐标基准。当前 ActiveArea 从 `(0,0)` 开始、crop origin 为偶数，所以相位不变；通用实现必须显式换算，不能把数组文件左上角、ActiveArea 左上角和 DefaultCrop 左上角混为一处。

Dark Shading 校正后的网络输入允许小于 0，只裁上界：

```python
input_norm = torch.clamp_max(input_norm, 1.0)
target_norm = torch.clamp(target_norm, 0.0, 1.0)
```

把输入下界裁到 0 会破坏真实暗帧 residual 的负半边分布。

## 5. Dark Shading（Dark Shadow）的计算、保存和使用

### 5.1 条件分桶

Dark Shading 和 residual 的 condition key 至少包含：

```text
camera_id
sensor_mode_id（镜头、分辨率、binning/HDR/RAW mode、CFA、尺寸）
iso_exif
exposure_time
thermal_bin 或 capture_session
```

当前文件没有可靠的温度 sidecar，因此至少按拍摄批次和时间段保存，不能假定 7 月 24 日暗帧与 7 月 26～28 日 clean/未来测试时的热状态相同。后续采集 app 应同时保存 request 与 CaptureResult，包括 sensitivity、exposure、frame duration、noise profile、dynamic black/white、lens/sensor mode 和可用温度。

### 5.2 定义与计算

对条件 `q` 内第 `j` 张暗帧，先展开该帧的 black map：

\[
D^0_j(p)=\operatorname{linearize}(D_j(p))-b_j(p).
\]

用 sigma-clipped mean 或 robust mean 计算：

\[
DS_q(p)=\operatorname{robustMean}_{j\in q}D^0_j(p),
\]

并保留有符号 residual：

\[
R_j(p)=D^0_j(p)-DS_q(p).
\]

关键约束：

- 全部在原始 DN 域计算，直到最后一步才归一化。
- `DS` 与 `R` 使用 `float32`，不能先 clip，也不能保存成无符号整数。
- 稳定热像素属于 DS/defect map；瞬时异常用 sigma clipping 隔离。
- 最佳方案是把 DS-calibration 帧与 residual-sampling 帧完全分开。同一组 N 帧同时求普通均值 DS 和 residual 时，residual 方差会缩小为原方差的 `(N-1)/N`，可乘 `sqrt(N/(N-1))` 修正；leave-one-out residual 的方差反而会放大为 `N/(N-1)`，要乘 `sqrt((N-1)/N)`。robust estimator 没有这么简单的解析修正，应以 held-out 暗帧实测方差定标。
- DS 精度要在留出的暗帧上检查：`mean(R)`、通道方差、row/column autocorrelation、分位数和热像素残差，而不是只看平均灰度。

当前每档只有 10～30 张，适合原型和低频平滑 DS，不适合宣称获得高精度逐像素 DS。工程上可先以每个 `(mode, iso_exif, exposure, thermal bin)` 50～100 张为补采预算，但这不是规范阈值；最终应报告 N、held-out 误差和置信区间。若要精确建模曝光/暗电流，应增加多个曝光档并拟合 `DS(p,t)=a(p)t+b(p)`，不能拿 1/30 s 直接代替 10 s。

### 5.3 推荐保存结构

```text
data/MEY_AN00/
├── manifests/
│   ├── all_dng.jsonl
│   ├── clean_train.jsonl
│   ├── clean_val.jsonl
│   ├── clean_test.jsonl
│   ├── dark_train.jsonl
│   ├── dark_val.jsonl
│   └── dark_test.jsonl
├── calibration/
│   └── <condition_key>/
│       ├── metadata.json
│       ├── dark_shading_dn.npy      # float32, [4,H/2,W/2]
│       ├── defect_mask.npy          # bool, [4,H/2,W/2]
│       └── calibration_frames.json
└── clean_masters/
    └── <scene_id>_<condition>.npz
```

`metadata.json` 至少保存：算法版本、condition key、canonical 通道顺序、原始 CFA、artifact 坐标基准（完整 ActiveArea 或 DefaultCrop，只能选一种）、crop、shape、Black/White Level、统一归一化分母 L、`units=linearized_DN`、`black_subtracted=true`、`ds_includes_black=false`、`domain=pre_opcode`、linearization/opcode policy、输入文件列表与 hash、估计器及阈值、帧数、采集时间/温度代理、每通道 DS/residual 统计和 `NoiseProfile`。读取时必须断言坐标与域，避免重复 crop、重复减黑或把 DS 错位 8 像素。

无需复制保存全部全分辨率 residual。保留原始 DNG 为只读文件，在 DataLoader 中按 manifest 加载 crop，并计算 `dark-B-DS`；如 I/O 成为瓶颈，再缓存 signed float16/float32 packed residual，且用数值测试确认没有分布变化。

### 5.4 训练与推理必须采用同一种 DS 协议

推荐 baseline 是“网络前校正 DS”：

```text
训练 clean target:  linearize(raw_clean) - b_clean - DS_clean_condition
训练 dark residual: linearize(raw_dark)  - b_dark  - DS_dark_condition
推理 noisy input:   linearize(raw_noisy) - b_noisy - DS_noisy_condition
```

合成时只加入 residual `R`，不再加入 DS。这样网络学习随机/相关噪声，不负责记住拍摄时的固定偏置。实验中应冻结同一份仅由 DS-calibration 帧生成的 artifact，并原样用于 residual train/val/test 和对应部署协议，不能为每个 split 重新计算一张更有利的 DS。

另一种实验是让网络学习 DS：合成时加入 `DS+R`，推理只减 B。此时 clean crop、DS 和暗帧 residual 必须保持相同传感器绝对坐标，不能独立随机裁剪；模型也更容易过拟合固定位置。两种协议不能在训练和推理间混用。

## 6. clean target 与未来 noisy-clean 对的采集

### 6.1 clean target

正式 clean target 建议：

1. 固定镜头、sensor mode、分辨率、focus、white balance 和 tripod。
2. 优先低实际 ISO，调整曝光使主要区域有充分信号且不过曝。
3. 每个静态场景采 8～16 张以上完全相同条件的 long-exposure burst。
4. 每帧减对应的 B 和曝光/温度匹配 DS，在 linear RAW/DN 域配准、剔除运动和异常帧，再做 sigma-clipped mean。
5. 保存 `clean_master_dn`、源帧列表、对齐变换、有效 mask、饱和 mask 和平均后的残余噪声估计。

如果只能使用当前单张 10 s DNG，应称为 pseudo-clean，并在 patch 级做以下过滤：饱和比例、BlackLevel 以下比例、局部信号强度、模糊/运动、坏点和依据 `S/O` 预测的 target noise。高 ISO 单帧不应与 burst master 等价处理。

### 6.2 未来真实 noisy-clean 对

真实对用于 validation/test 和最终 domain-gap 判断，不应全部投入训练：

1. tripod 固定同一场景，先记录一个 `scene_id`。
2. 采目标短曝光 noisy burst，保存每帧最终 EXIF/CaptureResult，而不是只记 UI 设置。
3. 立即采 long-exposure clean burst并平均；必要时在前后各采一组，检测照明漂移。
4. 同实际 ISO 时，初始亮度比可用 `r=t_clean/t_noisy`；ISO 不同时必须在未饱和静态区域做线性响应回归或独立辐射标定，不能只用曝光时间比。
5. noisy 和 clean 分别减自己的 B/DS，再做 RAW 域亚像素配准和有效区域裁剪。
6. 保存 scene、burst、session、mode、实际 ISO、曝光、ratio、温度代理、profile、配准误差和质量标记。

当前 10 s 与 1/30 s 的曝光比约 300，恰好可做 ratio=300 原型；但只有未来 noisy 场景也确实是同 mode/实际 ISO/1/30 s，且 clean 的辐射尺度与目标一致时，这个 ratio 才能直接使用。

### 7.1 单帧记录格式

建议使用可审计的 JSONL，而不是靠目录名推断：

```json
  "camera_id": "HONOR_MEY-AN00",
  "sensor_mode_id": "mey_an00_3048x4064_GBRG_mode_unknown",

```

manifest 构建时应断言：相机/mode/CFA/尺寸一致、曝光与目录意图相符、Black/White 合法、`NoiseProfile` count 是 2 或 `2×ColorPlanes`、`S` 有限且 `>0`、`O` 有限且 `>=0`，以及同一 condition 的 profile 是否一致。当前本机期望 3 对参数；4 张错桶文件应由这一步自动报告。

### 7.2 clean/noisy 场景划分

必须先按 `scene_id`/地点/视角/拍摄序列分组，再划分场景，最后生成 patch：

```text
scene groups: 70% train / 15% validation / 15% test
```

同一地点的近似视角、同一场景的所有 ISO/曝光/burst、由同一 clean master 裁出的全部 patch 必须在同一个 split。当前水槽、鞋架、墙角/纸箱等重复视角需要人工或视觉检索合并成 scene group，不能直接对 90 个文件随机洗牌。

若独立场景太少，使用 grouped K-fold；不要退回 patch-level random split。划分时按实际 EXIF ISO、亮度、mode 和场景类别分层，并把 group 列表固化到版本化 manifest。

### 7.3 暗帧划分

暗帧也应按 capture session/thermal sequence 分组，避免相邻连续帧随机落入不同 split。正式数据应有独立的：

```text
DS calibration frames
residual train frames
residual validation frames
residual test frames
```

当前数据不足以四路稳健划分。仅做原型时，可在每个实际 ISO 内按时间块做 60%/20%/20%，得到约 80/27/27 张 dark train/val/test：用 60% 组估计临时 DS 并对其训练 residual 做上述有限 N 方差修正，另外两组保持 held-out；但每个低样本档的 val/test 只有 2 张左右，结果只能作 smoke test。正式实验应补采后把 DS-calibration 与 residual pool 完全分开。

模型选择使用固定 synthetic validation seed 和未来真实-pair validation。真实-pair test 场景在所有模型、阈值和早停确定前保持锁定。模型最终冻结后，部署 DS 可以用允许的全部校准暗帧重算，但不能反过来用 test pair 调超参数。

## 8. 推荐的手机噪声合成

### 8.1 hybrid 路线（主实验）

设 `X` 是已去 B/DS、按 DNG 统一有效范围 L 归一化的 clean target；`r` 是 noisy 短曝光增亮到 target 的辐射倍率；`S4` 是目标 noisy condition 的 DNG profile 展开到 canonical `[R,G1,G2,B]`；`R_dark_dn` 是同 condition 的真实暗帧 residual：

\[
\mu_{short,c}=\frac{X_c}{r},
\]

\[
Z_c=S_c\,\mathcal P\!\left(\frac{\mu_{short,c}}{S_c}\right),
\]

\[
Y_c=r\left(Z_c+\frac{R_{dark,c}}{L_{dark}}\right).
\]

```python
def synthesize_phone(clean_norm, ratio, S4, dark_residual_dn, L_dark):
    # S4 is [4,1,1]; scalar L_dark belongs to the sampled noisy/dark condition.
    mu_short = torch.clamp(clean_norm / ratio, min=0.0)
    shot_short = S4 * torch.poisson(mu_short / S4)
    residual_short = dark_residual_dn / L_dark
    noisy = ratio * (shot_short + residual_short)
    return torch.clamp_max(noisy, 1.0), torch.clamp(clean_norm, 0.0, 1.0)
```

这里的 `S4`、`L_dark` 和 dark condition 来自**要模拟的 noisy 相机设置**，不是 clean-source 文件自身的 ISO/动态范围。真实 `R_dark` 已包含 O-like read noise，也可能包含暗电流 shot、row/global、量化、RTS 和剩余结构项，因此必须匹配 noisy 的 mode、iso_exif、exposure 和热状态。当前 SID Dataset 把 clean EXIF ISO 同时当作噪声条件的做法不适用于自由采样手机噪声档位。

不过，只有验证跨 ISO 的线性响应并把 clean source 映射到目标 radiometric domain 后，才能自由独立采样 noisy condition。完成该标定前，baseline 应限制在同 sensor mode、同响应/增益段，或使用真实 pair 拟合的 photometric ratio，不能认为两个 ISO 下的归一化值天然等价。

### 8.2 analytic fallback

没有真实暗帧时才使用。`r=1` 时可写为：

\[
Y=S\,\mathcal P(X/S)+\sqrt{O}\,\mathcal N(0,1).
\]

有曝光倍率时，应在短曝光域采样 `sqrt(O4)·N`，再与 shot 一起乘 `r`。

这条路线无法复现真实 row/column/FPN/热像素/量化相关结构，只能作为消融或 fallback。不能同时加入完整 `R_dark` 和 `sqrt(O)N`。

### 8.3 PRNU 与位置模式的后续扩展

暗帧无法估计光照相关 PRNU。若真实 pair 上仍有明显域差，可增加少量多亮度平场：

- 拟合 PTC 抽验 `S`；
- 估计 gain/PRNU map；
- 检查 DCG/数字增益拐点；
- 判断两个绿色通道是否需要独立参数。

对于绝对位置稳定的列噪声、边缘 shading 和 defect map，要么在推理前校正，要么训练时保持传感器坐标；随机挪动 full-frame FPN patch 会改变其物理含义。

## 10. SID NAFNet-Tiny 微调还是从头训练

### 10.1 推荐：先微调

当前目标仍是 4 通道 packed RAW 到 4 通道 clean RAW，NAFNet-Tiny 的空间结构和去噪先验可迁移；而当前只有 90 张单帧 clean source、134 张暗帧，独立场景更少，从头训练很容易记住场景和噪声样本。因此主实验建议：

- 保持与预训练完全相同的 NAFNet-Tiny 结构：width 16，encoder/decoder `[1,1,1,1]`，middle 2；
- canonical 通道固定为 `[R,G1,G2,B]`；
- 加载本地 `experiments/sid_sony_nafnet_tiny/checkpoints/latest.pth`；
- 全网络微调，初始学习率从 `1e-5～2e-5` 搜索，使用新的 optimizer/scheduler；
- 当前 pseudo-clean 只跑 10～100 step 的数据/梯度 smoke test；补齐独立 scene、clean master 和固定 validation 后，再从约 50k step 的正式基线起步并早停；
- patch 可沿用 packed 512×512，但要从不同 scene/绝对位置充分采样；
- 使用新的输出目录，记录源 checkpoint hash、manifest hash、DS artifact 版本和 noise-profile 表。

现有 `train_sid_sony.py` 的 checkpoint 加载语义已经满足初始化需求。手机 DataLoader 和训练入口实现后，命令应类似：

```bash
# train_phone.py/config 目前尚未实现，不能直接执行这一命令。
python train_phone.py \
  --config configs/train_mey_an00_nafnet_tiny.yaml \
  --init-checkpoint experiments/sid_sony_nafnet_tiny/checkpoints/latest.pth \
  --output-dir experiments/mey_an00_finetune
```

手机适配完成后，应在 `train_phone.py` 保留同名 `--init-checkpoint` 参数。不要使用：

```bash
--resume experiments/sid_sony_nafnet_tiny/checkpoints/latest.pth
```

因为 `--resume` 会连 SID 的 optimizer、scheduler、epoch 和 global step 一起恢复；训练已到 epoch 1000，学习率状态也不适合新的手机 run。当前 checkpoint 加载函数使用 `strict=True`，所以初始化时架构必须完全相同。若新入口按总 step 控制正式微调，还需新增 `max_steps`；现有入口只有 epoch 和可选 `steps_per_epoch`。

### 10.2 必做的 scratch 对照

从头训练不是首选，但必须作为公平对照。两组实验应使用完全相同的：

- scene/dark split；
- clean crop 与合成噪声样本（可固定 sample manifest/seed）；
- optimizer steps、batch、loss 和验证频率；
- 最终真实 noisy-clean validation/test 协议。

比较顺序建议为：

|实验|初始化|目的|
|---|---|---|
|A（主线）|SID NAFNet-Tiny，full fine-tune|验证 RAW/结构先验的迁移收益|
|B|random init|判断 Sony domain prior 是否有负迁移|
|C（可选）|SID init，前若干层短暂冻结后全部解冻|数据极少时诊断过拟合|

只有当补采到大量独立 clean scene/真实 pair，且 scratch 在锁定的真实 test 上稳定优于微调，才把 scratch 升为主方案。现在没有真实 pair 时，synthetic validation 只能检查代码和过拟合，不能可靠决定 A/B 谁在真实手机噪声上更好。

### 10.3 增加 noise map/metadata 条件输入时

当前权重首层是 4 通道，而且现有 NAFNet 的全局残差会把输入直接加到 4 通道输出。若第二阶段加入 `S/O` noise map、ISO、曝光或温度，不能简单修改 `img_channel`：需要独立 conditioning stem，或让主干显式只输出并残差连接前 4 个 RAW 通道。此时 `strict=True` 也无法直接加载首层；应先完成纯 4 通道 baseline，再为扩展模型加载 shape 匹配层、复制 RAW 四通道权重并对新增分支做零/小值初始化。该路线必须单独报告。

## 11. 推荐执行顺序

1. **冻结原始数据。** 不改 DNG，生成带 hash 的 `all_dng.jsonl`；按 EXIF/profile 重分桶并标记 4 张错目录文件。
2. **实现并测试 DNG parser/CFA pack。** 先让一张文件完成 stored mosaic → canonical packed → inverse round-trip。
3. **建立 NoiseProfile 查找表。** 每帧保留原值；表格缓存只用于加速和一致性检查。
4. **补采暗帧。** 覆盖最终 noisy 曝光、实际 ISO、mode 和冷热状态；另采 10 s 暗帧用于 clean target 校正。
5. **标定并版本化 DS。** calibration 与 residual frame 分离；在暗帧 val/test 上验证。
6. **整理 clean scene group。** 当前数据先做 pseudo-clean smoke test；正式补采低 ISO clean burst master。
7. **固化 scene/session split。** 先 split 再 crop，真实 pair test 锁定。
8. **实现 hybrid 合成和确定性 synthetic validation。** 在短曝光域检查 `Var=S·μ_short+Var(R_dark/L)`，增亮后检查 `Var(Y|X)=r·S·X+r²Var(R_dark/L)`；analytic fallback 则为 `r·S·X+r²O`。同时比较 row/column autocorrelation 或 PSD，确认经验相关结构存在且没有重复 O。
9. **加载 SID 权重做全网络低 LR 微调。** 同时跑等预算 scratch 对照。
10. **补齐真实 noisy-clean pair 后再做最终选择。** 报告各实际 ISO/曝光/温度段的 RAW PSNR/SSIM、噪声残差统计和可视化，不只报告 synthetic 指标。
