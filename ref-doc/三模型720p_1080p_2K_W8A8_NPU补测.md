# 三模型720p、1080p及2K分辨率 W8A8 NPU补测

日期：2026-10-10。本次新测三档分辨率、三个模型，每项3轮×100次，共2700个样本。只比较推理速度，未训练、未评估量化画质。

## 1. 输入定义与测试口径

| 档位 | 原始Bayer RAW宽×高 | 未补边packed H×W | 实测NCHW输入 |
|---|---|---|---|
| 720p | 1280×720 | 360×640 | `[1,4,368,640]` |
| 1080p | 1920×1080 | 540×960 | `[1,4,544,960]` |
| 2K（本次指2560×1440） | 2560×1440 | 720×1280 | `[1,4,720,1280]` |

按用户确认，packed高宽严格向上对齐16：`ceil(size/16)*16`。720已经整除16，因此2K不补到736。前期736高度产物归档于 `excluded_2k_736`，不纳入本报告。外部补边、裁剪、ISP耗时均不包含在模型耗时内。

设备Samsung Galaxy S24，日志核对SM-S921U1 / SM8650 / Hexagon V75；QNN DLC、QAIRT 2.50.0.260828221209、qai-hub 0.56.0。权重/激活8bit，IO量化；平台随机数据校准，仅用于速度比较。每项汇总全部300个样本，P50/P95线性插值，不剔除首个较慢样本；不包含上传、排队或编译时间。运行条目全部为NPU。云端同型号不保证同一台物理手机。

本次1080p也重新编译、测速。三档沿用相同权重快照：Rep-NCB使用已训练epoch 50权重；单DW3残差继续沿用之前seed=2026的未训练HF替换模块，LL及精修来自原基线；MRLFN沿用原best权重。同模型跨分辨率不改变权重，不据此比较画质。

## 2. 速度与Rep-NCB相对MRLFN的优势

以下“降低延迟”=`(MRLFN耗时−Rep-NCB耗时)/MRLFN耗时`；“节省毫秒”=`MRLFN耗时−Rep-NCB耗时`。负数表示Rep-NCB更慢。倍率=`MRLFN耗时/Rep-NCB耗时`。

| 输入档位 | Rep-NCB / ms | DW3残差 / ms | MRLFN / ms | Rep-NCB节省 / ms | 降低延迟 | 速度倍率 |
|---|---:|---:|---:|---:|---:|---:|
| 720p | 0.9827 | 0.7949 | 0.7946 | -0.1881 | -23.68% | 0.809× |
| 1080p | 1.8168 | 1.5688 | 2.2287 | +0.4119 | +18.48% | 1.227× |
| 2K | 3.4471 | 4.2237 | 4.8669 | +1.4198 | +29.17% | 1.412× |

本次三档中，Rep-NCB相对MRLFN的**百分比优势最大为2K**（降低延迟29.17%）；**绝对节省最多为2K**（每次1.4198 ms）。这是本次样本的点估计；若差距接近轮间波动，不应宣称稳定优势。

2K下Rep-NCB也比单DW3残差降低约18.39%的延迟；720p和1080p则是单DW3更快。这个排序反转描述的是当前编译产物，不能仅归因于某一个高频算子。结合此前4K下Rep-NCB反而慢于MRLFN的结果，优势不是随分辨率单调增大；这里只能确定已测离散尺寸中2K表现最好，不能声称找到了所有输入尺寸的最优点。

## 4. 与此前4K结果对照

4K为此前测得的 `[1,4,1088,1920]`，不是本轮重测；相同权重和编译设置，但测试批次不同。

| 档位 | Rep-NCB / ms | DW3残差 / ms | MRLFN / ms | Rep-NCB相对MRLFN降低延迟 |
|---|---:|---:|---:|---:|
| 此前4K | 10.1631 | 9.4048 | 9.3688 | -8.48% |

分辨率上升同时改变计算量、特征读写规模以及编译器的分块、融合选择；固定开销占比也会变化。因此，低分辨率的速度比例不能按像素数直接外推。当前记录只确定实际耗时趋势，没有独立测出缓存或DDR带宽瓶颈，不能把潜在原因当作已证实归因。

## 6. 复现命令

以720p为例；1080p将标签/高/宽换成1080p/544/960，2K换成2k/720/1280。重测需使用新结果目录，原目录会恢复已有任务。导出若覆盖ONNX，应根据新导出JSON更新sources.json的source_sha256。

```bash
PYTHONPATH=/tmp/sid-onnxsim python tools/export_sid_npu_ablation.py \
  configs/deploy/haar_hf_repncb_prelu_residual_sweep_720p.yaml \
  configs/deploy/haar_hf_cnn_dw3_residual_sweep_720p.yaml \
  configs/deploy/mrlfn_sweep_720p.yaml \
  --output-dir experiments/npu_resolution_sweep_20261010/onnx

read -r -s -p "AI Hub API token: " QAI_HUB_API_TOKEN
export QAI_HUB_API_TOKEN
PYTHONPATH=/tmp/sid-qai-hub python tools/benchmark_sid_qaihub.py \
  --watch --height 368 --width 640 \
  --sources-json ref-doc/qaihub_resolution_sweep_20261010/720p/sources.json \
  --output-dir ref-doc/qaihub_resolution_sweep_20261010/720p
unset QAI_HUB_API_TOKEN
python tools/summarize_sid_qaihub.py \
  --output-dir ref-doc/qaihub_resolution_sweep_20261010/720p
```

`/tmp`依赖目录为当前机器环境；导出使用PyTorch 2.1.2、ONNX 1.16.2、ORT 1.18、onnxsim 0.4.36，其他机器需安装对应依赖。
